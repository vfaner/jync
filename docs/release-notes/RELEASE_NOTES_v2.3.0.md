# Jync v2.3.0

## 新增

- **ETL SQL 变量**：取数 SQL（含脚本里的前置语句）、预执行 SQL、后处理 SQL 与范围条件支持 `${name}`；任务表单新增「SQL 变量」文本框，一行一个 `name=value`。内置 `date`（yyyy-MM-dd）、`datetime`（yyyy-MM-dd HH:mm:ss）、`yesterday`、`month`（yyyy-MM）、`year`、`taskName`、`targetTable`；`targetTable` 与运行实际写入的表一致（目标连接配置了模式时带模式前缀）。值原样插入，不加引号、不转义、不二次扫描；未知变量在保存、预检、运行三处报错；修改变量与修改取数 SQL 一样清除断点，运行中拒绝编辑；配置包携带变量，旧包缺字段可照常导入。
- **ETL 目标表列交集写入**：目标表已存在时按列名（不区分大小写）写交集，取数结果多出的列跳过并记警告，跳过的列名以 `skipped=列1,列2` 出现在最近运行结果里。一列都对不上、或 UPSERT 主键被跳过时，在预检与 pre-sql / 写模式 DELETE 之前失败，不会先清空目标表。
- **ETL 写入方式联动**：范围条件、续传键、主键列三个字段只在所选写入方式会读取时显示；首屏由服务端渲染，切换下拉即时跟进。隐藏只改可见性、不禁用字段，来回切换不丢已填内容，服务端仍按最终模式校验。

## 优化

- **ETL 大字段与时间类型**：Oracle 文本内联绑定上限从 32767 收到 CLOB 的 4000 字节、二进制按 RAW 的 2000 字节分流，超出后走 LOB 绑定，修复 4001～32767 字节文本的 ORA-01461；ETL 取数游标改走同步读取器的取值路径，LOB 整块读成 String / byte[]，DATE、OTHER、ARRAY、带时区时间戳与 MySQL TIME 的取法与同步侧一致。
- **ETL 预检与保存同一口径**：只校验当前写入方式会执行的字段。非续传模式残留的续传键、非范围覆盖残留的范围条件，不再挡住保存、预检或运行；预检也不再对运行不会执行的续传键报错。

## 修复

- **UPSERT 唯一索引误判**：探查唯一索引时按语句实际解析的 schema 收窄，不再以「所有 schema」调用 `getIndexInfo`，另一个 schema 下同名表的唯一索引不会再替目标表作证。PostgreSQL 不再因误判发出会被拒绝的 `ON CONFLICT`，MySQL 系不再静默重复插入。
- **ETL 结果列边界**：大小写折叠后重复的列名在写入前即拒绝，不再等到写模式 DELETE 之后才失败；UPSERT 主键为 NULL 的报错指向实际写入列；取数结果缺少主键列改为可翻译的 `error.etl.upsertKey.missing:<key>`；主键配置重复（`id, id`）去重，避免生成数据库必然拒绝的 `PRIMARY KEY (id, id)` 与 `ON CONFLICT (id, id)`。
- **续跑键类型**：PostgreSQL `timestamptz` 续跑键绑定其携带的时刻，而不是驱动渲染的文本，续跑查询不再因 `timestamptz > varchar` 失败。
- **批次成员表单重渲染**：保存校验失败或预检后，成员任务不再显示成独立任务；批次横幅、锁定的连接与「调度归批次」提示保持正确。修正预检按钮的图标标签未闭合。

## 已知边界

- SQL 变量只识别 `${name}`（ASCII 标识符），没有转义语法；值原样插入，含引号或分号时 SQL 结构是否成立由编写者负责。日期变量按运行 / 预检开始时的 JVM 默认时区取值，多节点时区不一致会得到不同日期；日期变化不会触发断点重置，跨天续跑仍可能沿用昨天保存的水位（详见已知限制第 15 节）。
- 列交集写入只写同名交集：取数结果多出的列不写入；目标表多出的列保持原值或默认值，非空且无默认值的列会让首行插入失败，预检对此只给警告（详见已知限制第 14 节）。
- 目标库账号读不到表元数据时无法计算交集，运行回退为按结果整行写入并记录警告，由目标库的 INSERT 报错兜底。

升级只需替换 `jync.jar` 并重启；`etl_task` 新增可空的 `variables` 列，由启动时的元数据库更新自动补齐，既有任务、连接与配置包无需迁移（旧包缺少变量时按空处理）。运行环境仍需 Java 17 或更高版本。
