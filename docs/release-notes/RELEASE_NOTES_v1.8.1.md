# Jync v1.8.1

批量创建同步任务：读一次源库表清单，按估算大小自动分箱，预览后一次创建多个停用任务。另修复批量统计在 Oracle 系与 SQL Server 上的取数问题，并加固 CSV 导出。

## 新功能

### 批量创建任务

- **入口**：任务管理页「新建任务」旁新增「批量创建」（仅管理员）。选择源/目标连接、任务数（1–50，默认 8）与名称前缀，读取一次源库目录统计后按估算大小分箱。
- **分箱**：按估算行数从大到小，依次放进当前最小的箱（LPT）。大小未知的表按已知大小的中位数计入；全库无统计时按表数均衡。结果确定：同样输入在预览和创建时得到同样的分箱。
- **统计来源**：优先用产品目录（MySQL `information_schema`、PostgreSQL `pg_class`、Oracle `ALL_TABLES`、SQL Server `sys.partitions`、DB2 `SYSCAT.TABLES`），不扫表。勾选「精确统计行数」才对未知表逐条 `COUNT(*)`：单表 15 秒、整页 120 秒预算，超预算停止并在页面注明。
- **预览**：显示每个任务的表清单、估算行数与统计来源；没有估算的表单独计数，不计入合计；可导出 CSV（UTF-8 BOM）。
- **创建**：一个事务里创建全部任务，名称重复时在建任何任务之前拒绝；新任务一律为「未启动」，采集方式与选表随表单，逐表确认后再启动。
- **不打扰同步**：规划只使用独立的两连接临时池（与「测试连接」同一条路），不占用同步连接池，也不影响正在运行的同步任务。

## 修复

- **停用任务上的重建基线**：过去会短暂启动消费者、占用同步锁并开始全量，随后被巡检停掉，页面同时显示「已停止」和「CDC 运行中」。现在停用状态只清空进度、错误标记与遗留的错误文本（服务端强制，直接调接口也一样），不会启动消费者；启用任务后才重新执行全量。确认框与接口提示同步说明这一点。
- **停用任务切换采集方式**：把一个未启动的任务切换到日志 CDC 时，过去同样会立即启动消费者跑全量，随后被巡检停掉。现在只重置基线与错误状态，消费者在任务启动时才拉起；批量创建出的 CDC 任务因此真正保持「未启动」。
- **Oracle 系 schema 大小写**：连接配置里写成小写 schema（如 `scott`）时，「精确统计」拼出的 `COUNT` 语句引用一个不存在的 schema，每条统计都静默失败、全部显示未知。现在按同步链路的规则先折叠为大写。
- **SQL Server 行数被重复计数**：目录统计把分区与其分配单元直接连接，一个分区通常有 in-row、LOB、行溢出多个分配单元，行数因此被重复累加，含大字段的表会显示成数倍大小。现在先按分区聚合分配单元再连接。
- **空表被当成未知**：`COUNT(*)` 返回 0 是已知大小，分箱时却按中位数计重，空表越多分箱越偏；目录统计返回 0 也有同样问题。现在 Oracle `NUM_ROWS`、SQL Server 分区行数、DB2 `CARD` 的 0 按空表计重，并保证全为空表时仍按数量均分。MySQL `TABLE_ROWS` 未收集统计时也读作 0，无法与空表区分，仍按未知处理；PostgreSQL 14 起未收集统计的表读作 -1，0 即空表（9.4–13 仍按未知）。这些表可用「精确统计行数」补齐。
- **预览提示与实际统计不符**：用精确统计补齐大小后，页面仍显示「该库未提供目录统计，所有表大小未知」；目录只报告字节数、行数尚未收集时也一样。现在只有目录与精确统计都没有任何结果时才提示。
- **源库短暂不可达会停掉 CDC**：Oracle LogMiner、PostgreSQL 逻辑复制与 SQL Server CDC 把「连不上源库」和「写目标端失败」记进同一个连续失败计数，一次约半分钟的网络抖动就会把项目置为错误状态、需要人工清除。现在只有应用数据失败才累计并停用，源端连不上按退避无限重连（与 MySQL 消费者一致）。
- **停止 CDC 可能被建连卡住**：消费者启动时建立两端连接的过程原先占着管理器锁，期间点「停止」要等连接超时后才返回。现在连接在锁外建立，停止会立即返回；若停止发生在建连期间，启动方放弃注册并释放租约。
- **批量创建的重名窗口**：过去整个规划（含最长两分钟的精确定时）都在一个事务里，重名检查与写入之间的窗口被拉长到分钟级，并发创建可能写入重名任务（`Project.name` 无唯一约束）。现在先规划、后开事务，检查与写入相隔毫秒级，规划期间也不占用元数据库连接。
- **「同步行删除」的说明**：补充「日志 CDC 下只在基线加载完成后执行一次，之后的删除由日志流同步」，避免被理解为每条变更都做全表比对。

## 安全加固

- **CSV 导出防公式注入**：表名与任务名可被构造为以 `=`、`+`、`-`、`@` 开头的单元格，表格软件打开导出文件时会当作公式执行。现在这类字段前加单引号，普通名称不受影响。

## 兼容性说明

- **默认行为不变**：不进入「批量创建」页面就不会读取任何表清单；已有同步任务、调度与 CDC 行为不变。
- **无数据库结构变更、无新增配置项**。替换 `jync.jar` 重启即可；容器部署将镜像 tag 更新为 `jync:1.8.1`。升级前备份 `./data` 与 `application.yml`。
