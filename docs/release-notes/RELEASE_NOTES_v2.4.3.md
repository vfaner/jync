# Jync v2.4.3

## 新增

- **AI 运维助手可以执行运行态操作，但每一次都由人确认**：启动 / 停止同步任务、立即同步一次、启用 / 停用 / 立即运行 ETL 任务、启停 / 立即运行 / 取消专属迁移、重建 CDC 基线，助手只生成**确认卡**；点「确认执行」后由服务端按当前账号的角色与资源归属重新校验一次才生效。确认令牌绑定发起账号、5 分钟有效、只能使用一次；并发确认只会执行一次，资源归属在生成与点击之间变更时以权限不足拒绝。删除任务、修改配置与连接、系统设置、外部认证、告警、AI 配置、用户与审计没有对应工具，助手触达不到，也不能执行 SQL；每次执行写审计 `AI_SUPPORT_ACTION`。
- **症状诊断与建议式回答**：新增 `diagnose_project`、`diagnose_etl_task`、`diagnose_migration`、`recent_failures`、`list_migrations` 五个工具，一次取齐任务状态、最近失败、生效告警、CDC 位点与恢复开关、ETL 最近运行行数、迁移索引与文档进度，避免把工具调用预算耗在逐个查询上；回答按「结论 → 依据 → 建议 → 可执行项」组织，可执行项最多两张确认卡。工具进度改为服务端四态（等待进行 / 正在进行 / 已完成 / 失败），流中断时未完成的行统一显示失败。
- **知识库**：补充 TDengine 使用限制、CDC 停摆与重建基线、ETL 与专属迁移排障章节；检索片段上限从 600 字放宽到 2000 字，避免长章节把结论截掉。中英文两份同步更新，README 与数据边界文档同步修正。
- **助手可以直接分析粘贴的报错日志**：单条消息上限放宽到 8000 字，超长时保留开头与结尾并标出中间省略的字符数（异常通常在末尾，不再被截掉）；提示词要求引用日志里的异常类名、错误码或关键行，不编造日志里没有的内容，不复述日志中出现的密码、连接串与用户名，日志点名的任务再用诊断工具核对一次。

## 修复

- **MySQL / MariaDB 的 `TINYINT(1)` 不再被驱动折成布尔**：`jdbc:mysql:`（含 `+srv` 写法）与 `jdbc:mariadb:` 连接串统一写入 `tinyInt1isBit=false`，内置 MySQL 系预设、MariaDB、Doris 与用户自填的同协议 URL 都生效；旧配置里显式写的 `tinyInt1isBit=true` 会被改写为 `false`。此前 `status` 这类列在源端被读成 `true`、写到目标变成 `1`，基线与 CDC 两条路径都会失真，重建基线也纠正不回来；现在基线、CDC、ETL、数据预览与结构元数据都按数值处理，`5` 原样到达目标。OceanBase、GBase 等厂商自有驱动 URL 不加该参数，由已有的读写路径兜底。**存量数据不会自动回改，升级后重建一次基线即可全量纠正**；结构同步从 MySQL 系源建表时，MySQL 协议目标上 `TINYINT(1)` 按普通 `TINYINT` 建立，其他目标按宽一档的整数（`SMALLINT` / `NUMBER(3)` 等）建立，取值域与内容不变。详见[已知限制](../known-limitations.md) 4.8。
- **助手不再说废话**：提示词明确禁止开场白（「好的」「当然」「让我看看」）、复述用户问题、过程旁白（「我先查一下」「根据以上查询结果」）与结尾客套（「希望有帮助」「如有其他问题随时问我」），一句话能答完的不写第二句，简单查询 1–3 句，只有诊断类问题才用「结论 → 依据 → 建议」。调用工具的同一轮里写的过程旁白不再下发到浏览器——界面已有工具进度行，最终回答会重新给出结论；被纠偏的计划句同样不显示。工具轮次用尽后的收束轮额外要求「第一句就是结论，不说明过程、轮次或预算」。长回答仍边生成边显示，不受影响。
- **助手不再只说不做或空手结束**：工具调用之后只回「稍等，我再查一下」这类过渡句会被纠偏一次，要求立即调用工具或在同一轮给出结论；模型返回空内容时明确提示重试或换个问法，不再静默结束；工具轮次预算用尽时会带着已拿到的证据再做一次无工具收束回答，而不是直接报「工具轮次过多」。同时把轮次上限从 4 放宽到 8、整体预算从 90 秒放宽到 150 秒，长诊断不再中途被截断。
- **连接探活不再打断 Hikari 关池**：连接页 8 秒预算到期时，原来的取消会中断仍在运行的探活任务；中断若落在探活线程的 `HikariDataSource.close()` 里，Hikari 会把它当成立即停止，在第一个 `awaitTermination` 抛出，跳过连接回收等步骤，连接池只关了一半，并打出「Interrupted during closing」和整段堆栈，看起来像启动失败。现在到期只放弃等待、不中断工作线程，探活按 Hikari 自身的连接与校验超时在 daemon 线程上跑完并关闭连接池；取消后的清理也不再产生第二次中断。
- **启动失败页给出真实原因**：Hibernate 的「Unable to determine Dialect without JDBC metadata」是兜底提示，真正原因只被记在上一条 WARN 里。失败页现在会引用 `logs/jync.log` 末尾最后一条 `HHH000342` / `HHH100046` 异常行（口令脱敏、截断 300 字）；H2 文件库还会引用 `jync.trace.db` 最后一条带时间戳的诊断，并读取 MVStore 文件头报告写格式——写格式 2 正常，3 及以上说明库被 H2 2.2+ 写过、本版本内置的 H2 2.1.214 打不开，文件头认不出则提示可能损坏。
- **Hibernate 之前先查目录权限**：新增启动预检，在 Hibernate 打开元数据库之前，以 ERROR 记录元数据库目录或文件对当前运行用户不可写的情况。容器里 `/app/data` 属于 root、进程以 uid 10001 运行时，正是「trace.db 有记录、mv.db 未被修改、没有 `jync.lock.db`」这组指纹；预检只读文件系统，不打开、不修改库文件，诊断失败也绝不阻断启动。
- **旧库已有同名 `ops` 账号时升级不再启动失败**：2.3.0 及更早版本只有 ADMIN / VIEWER，现场常已存在名为 `ops` 的本地账号。播种插入第二个 `ops` 撞上用户名唯一索引，异常从启动监听器逃出，进程在「Started JyncApplication」之后退出，而且每次重启都复现。现在播种前先查用户名：已占用时保留原账号及其角色不动，每次启动留一条 WARN；账号改名或删除后下一次启动自动补出运维账号。
- **一键升级回滚不再卡住**：回滚前探测新进程端口，超时后先发 SIGTERM 等 15 秒；若新进程忽略信号（卡在关闭钩子或驱动线程不退出），现在在 Unix 上补 `kill -9`、Windows 上 `Kill()` 并再等 5 秒，避免回滚覆盖不了 jar 或留下两个进程抢同一个元数据库。
- **CDC 探测误判修正**：
  - SQL Server：`capture_instance` 名改用方括号定界，不再静默跳过合法的 Unicode / 空格名；自定义 `@role_name` 成员也视为已授权；扫完窗口后补 `advanceLsn`，避免整窗未映射表在重启后位点陈旧、保留期过后误判 PURGED。
  - MySQL：通过角色授予的 `REPLICATION CLIENT` / `BINLOG MONITOR` 计入判定；`auto_purge=OFF` 的短保留期改为通过并提示手工清理。
  - PostgreSQL：无主键表即使 `REPLICA IDENTITY FULL` 也判失败（消费者 upsert 需要主键）；`USING INDEX` 通过并提示核对索引覆盖。
  - Oracle 11g：接受 `EXECUTE_CATALOG_ROLE` / `DBA` 或 `EXECUTE ANY PROCEDURE` 作为 `DBMS_LOGMNR` 的执行权限，不再因 `SELECT_CATALOG_ROLE` 误判。
  - 崖山 YStream：容量检查扣除本项目自己的服务槽位，复用或重建不占新槽。
  - DDL 回放：内层 `error.ddl.*` 键不再被 `error.ddl.replay:` 包裹，页面能翻译 `tableMissing` 等真实原因。
- **助手确认卡**：重建基线在点击时补上归属校验，卡片生成后资源换了归属，旧账号也不能再执行；确认卡可能返回的结果键列入覆盖检查，不再把原始 key 直接显示给用户。
- 删除从未生效的 `sync.cdc.mssql.batch-size` 配置项（字段、设置页与文案），已知限制补充 SQL Server 窗口与单事务内存上限说明。

## 测试

6445 个测试：6444 通过，0 失败 0 错误；1 个仅限 Linux 的用例在 macOS 上按环境跳过。`*IT` 需 Docker 另跑；MySQL 8.0 容器上的基线 + CDC `TINYINT(1)` 往返（5 → 127）已实测通过。

## 升级

替换 `jync.jar` 并重启即可。从 2.3.0 及更早版本直接升级时，2.4.2 的枚举列文本映射与旧约束清理仍会在首次启动自动完成，数据无损；从 2.4.2 升级没有元数据库结构变更。运行环境仍需 Java 17 或更高版本。

如果升级后仍然起不来，失败页现在会直接列出底层错误、H2 诊断与目录可写性自检；把那段文字连同 `jync.trace.db` 末尾几行发出来即可定位。
