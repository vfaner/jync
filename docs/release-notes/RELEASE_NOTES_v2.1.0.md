# Jync v2.1.0

## 升级内容

- **CDC 结构变更（DDL）待办闭环**：源库执行 DDL 后不再只能靠人工翻日志。CDC 流遇到 DDL 时完整记录语句、开一条可跟踪的任务，管理员在页面上把目标库对齐，再把窗口内没同步的数据补齐。
  - **告警与日志**：新增 `DDL_SKIPPED` 告警类别（`isEvent()` 语义，消费者重启后计数下降会重新布防）；系统日志以 **ERROR** 输出未截断的完整 DDL；变更日志新增「**结构同步**」对象类型与 ERROR 行，默认折叠展示完整语句，对象名保留源库名。
  - **待办状态机**：变更日志行携带 `resolution_status`（待处理 / 已处理 / 失败）、DDL 是否已执行、是否已补齐、处理人与处理时间、可编辑的目标 DDL 语句、缺口起止位点与受影响表清单。日志保留策略只清理普通行与已处理行，**待处理任务不会被自动删掉**。
  - **弹窗操作**：点状态 tag 打开本页私有弹窗，可查看高亮 SQL、编辑语句后【在目标库执行】，或【重试补齐】；执行过 DDL 后【在目标库执行】禁用，补齐后【重试补齐】禁用，未执行目标 DDL 时【重试补齐】禁用并给出原因。需要补齐时**弹窗保持打开**，可直接接着点【重试补齐】；无缺口的语句才提示并刷新列表。
  - **补齐方式**：对缺口清单里的表从源库整表重读、用项目自身的表映射 / 列映射 / 类型转换做幂等 upsert 覆盖；目标是「重读覆盖」，**绝不清空目标表**。补齐成功后任务才转为「已处理」。
- **CDC 不再因表结构漂移停摆**：目标库缺少源端新增列时，写入只使用两端共有列（**主键列绝不裁剪**），其它列照常收敛；裁剪次数与「目标库缺源库列（已自愈）」计数上 CDC 状态面板，被裁掉的值不会静默消失。
  - **目标缺列自愈**：写目标若报 `Unknown column`（MySQL 1054 / 42S22、PG 42703、SQL Server 207、Oracle 904、H2 42122 等），自动打开列投影并让整个事务重放（位点不动），重放时裁掉缺失列后成功推进；不再反复撞同一个错，也不会把项目 park 成 ERROR。缺的是主键时无法裁剪，连续失败仍会按阈值停车等待人工处理。
  - **重启不留痕**：项目仍有未处理的 DDL 任务时，消费者启动即恢复列投影开关，不会因为运行期计数清零而重新触发一次失败日志。
- **按 binlog 事件身份记录 DDL**：DDL 任务按「binlog 文件 + 事件位置」去重，而不是按语句文本。同一事件因重连被重复投递只记一次；**同一条语句再次发生**——例如 `ADD COLUMN c` → `DROP COLUMN c` → 再 `ADD COLUMN c`——会作为新事件开新任务。位置同时作为缺口窗口的起点记录下来。
  - 一条语句会让**触及相同列的旧待办任务失效**：目标库已为某列对齐后，更早那条要求改这一列的任务自动转为已处理，避免同名列反复出现时堆一叠待办。
- **纯删除无需补齐**：只有 `DROP` 子句（或仅表级属性）的语句不留数据缺口，执行完直接转「已处理」；含 `ADD` / `MODIFY` / `CHANGE` / `RENAME` 的语句才需要补齐。目标库本来就没有要删的列时，MySQL 1091（`Can't DROP 'x'`）视为「目标早已对齐」而非失败。
- **架构归位**：DDL 任务的生命周期拆到 `CdcDdlTaskService`，`ChangeLogService` 回归纯审计日志；变更日志页的业务脚本独立为 `static/js/change-logs.js`，公共 `app.js` **与 v2.0.0 完全一致**。页面只复用既有的 `window.JyncUI` 提示框与 toast，弹窗显隐、带 CSRF 的提交、焦点管理都在本页脚本内实现，不往公共组件里塞业务代码。

## 修复与优化

- **DDL 解析**：子句拆分先剥掉（可能带库名限定的）表标识符，并正确处理引号内的逗号；`ADD` / `DROP` 子句分类不再把单个 `ADD COLUMN` 误判成无害语句，缺口判定与「旧任务取代」逻辑都据此工作。
- **提交校验与库名**：管理员只允许改 `COMMENT` 备注与方言细节（标识符引号、大小写、末尾分号），表名 / 列名 / 字段类型 / 子句顺序与源 DDL 归一化比对，不一致即拒绝且**不会打开目标库连接**。库名限定符写的是源库名，提交后由**服务端强制改写为目标库名**，管理员改不动它。
- **幂等执行**：`Duplicate column name`（MySQL 1060）视为目标已对齐；DDL 执行走独立事务，失败保留 FAILED 状态与错误详情供重试；执行动作由变更日志行自身的处理人 / 时间 / 语句留痕，不新增 `AuditAction` 枚举值（H2 的 `audit_event.action` 是固化 ENUM，新增值会报 22030）。
- **性能**：列投影只在「本次运行见过 DDL」或「写入证明两端已漂移」时启用，常态**零次**目标字典查询；有 DDL 时目标列集合按表缓存 30 秒（写被拒时立即失效）。
- **重复日志治理**：DDL 任务按 binlog 位置去重；同一 DDL 已有任务行时不再额外写一条 flush 失败行；flush 失败仍会带完整 DDL 写入 ERROR 变更日志并按 60 秒去重。
- **前端交互**：弹窗打开时把焦点移进 SQL 框、关闭前先移出（避免浏览器拒绝 `aria-hidden`）；用 JS 赋值后主动派发 `input` 事件，SQL 高亮垫层不再空白；取消 / 遮罩 / Esc 与两个按钮的禁用态由页面脚本自己管理，不影响其它页面的弹窗。
- **测试**：新增 `CdcDdlTaskServiceTest`（执行成功 / 失败 / 幂等 / 越权行 / 改名被拒 / 缺口收口 / 重放成功 / 未对齐拒绝 / 空清单不假闭环 / 库名改写 / 纯 DROP 直接完成 / 单子句 ADD 判定），并扩充 DDL 去重、binlog DDL 事件、列投影、DDL 任务视图等既有用例。

## 已知边界

- 被裁掉的列值**不在 binlog 可重放范围**（位点已推进），只能靠【重试补齐】的整表重读覆盖；补齐的是源表**当前状态**，窗口内后来被删除的行不会在目标端复活。
- 补齐是**表级整表重读**，大表耗时较长（前端有二次确认）；补齐期间 CDC 仍在写同一张表，幂等 upsert 保证最终一致，但存在瞬时覆盖竞争。不重建索引与统计信息。
- 缺口清单优先取运行期统计，消费者在 DDL 之后重启过则回退到「直接比对源 / 目标列集合」；管理员在目标库手工执行 DDL 后，元数据缓存最多 30 秒才反映新列。
- 目标库缺的是**主键列**时不能裁剪，连续失败按阈值停车；这类结构差异仍需人工在目标库对齐。
- Redis 目标不经 JDBC 写入路径，本次 DDL 待办与列投影不覆盖 Redis 同步项目。
- 变更日志的任务字段直接扩展在 `change_log` 行上（未拆独立任务表），全部可空，历史行不受影响；`ddl-auto=update` 会在首次启动时自动加列。升级前请照常备份 `./data`、外部元数据库与 `application.yml`；使用外部 MySQL / PostgreSQL 元数据库时建议先在副本上启动一次。
- 未引入行级暂存：管理员长时间不处理时会攒下大量行镜像与 LOB，容量与一致性风险大于收益。
- v2.0.0 的已知边界继续适用；`*IT` 集成测试仍需显式运行，不在 `mvn test` 默认范围。

---

升级只需替换 `jync.jar` 并重启；连接、同步项目、ETL、专属迁移与 TLS 证书配置均不需要迁移，运行环境仍需 Java 17 或更高版本。首次启动会给 `change_log` 增加任务相关列，请预留备份与启动时间。发布时请同步把 `pom.xml` 版本与 Dockerfile / Compose / K8s 清单、部署文档中的示例版本号统一为 2.1.0。
