# Jync v2.1.0

## 新增

- **CDC 流内 DDL 闭环**：源库运行中加列、改结构不再让 CDC 停摆。目标缺的列从行事件里剔除并计数，被跳过的 DDL 登记到【变更日志】，可在页面对目标库执行、重试补齐或关闭待办；新增「CDC DDL 被跳过」告警。
- **CDC 目标表被删自动修复**：识别到目标表缺失后，只重建这一张（或这几张）表并重灌数据，CDC 位点不动；连续失败 3 次（可配置）后停车等人工处理，修复成功写变更日志并发告警。
- **ETL「主键更新」（UPSERT）写入模式**：按配置的主键列，已存在则更新、不存在则插入。MySQL 协议族走原生 `INSERT ... ON DUPLICATE KEY UPDATE`，其他目标自动改用 UPDATE + INSERT 的等价实现；配置包导出与导入携带键列。

## 优化

- **变更日志错误行中文化**：CDC 写入失败、目标表缺失、停机结论等错误行与普通日志一样显示中文，`AUTH_FAILURE` 等英文代码保留，便于对照文档和检索日志。
- **外部认证设置页两栏布局**：桌面端左栏为通用设置、保存与连通性测试，右栏为认证方式设置与响应映射，页面不再冗长；窄屏自动收回单列。

## 修复

- **MySQL 元数据库长文本列**：30 个长字段显式建为 LONGTEXT，解决首次导入配置包报 error 1406；已升级的旧库在启动时自动加宽，单列失败只记 WARN 不阻断启动。
- **CDC 回放**：修正 MySQL DATETIME 回放时区偏移、redo 日志 IS NULL 解析受大小写映射影响、RENAME CONSTRAINT/PARTITION 误触发全表重放。
- **ETL 写入**：UPSERT 每次全量读取，不再沿用断点续传键；续传键只对追加与范围覆盖两种模式生效。
- **告警设置**：填写新 Webhook 地址时不再被「清除已保存的 URL」开关静默丢弃；密钥变更导致存量地址无法解密时页面不再 500。
- **专属迁移**：Mongo→Kingbase 语句失败后回滚、超长列名前置拒绝；Mongo→Mongo 按服务端身份识别同库，避免 OVERWRITE 误删源集合。
- **SQL 转换**：SQL Server 目标不再用 `SYSDATETIME()` 覆盖字面量默认值。
- **界面**：修复 ETL 预检卡片的两栏排版与间距，以及变更日志 DDL 弹窗在非根路径部署下的提交地址。

## 已知边界

- DDL 待办只覆盖表与索引语句；视图、存储过程、函数、触发器仍需人工对齐。
- 「重试补齐」按表整表重读并 upsert，目标端多出的行不会删除，大表可能耗时较久。
- 「主键更新」要求目标表在键列上有主键或唯一索引；CDC 定向修复只处理目标表缺失，结构不一致仍走流内裁剪。
- MySQL 元数据库自动加宽只处理本应用通过实体映射创建的表；内嵌 H2 仍固定 **2.1.214**。

升级只需替换 `jync.jar` 并重启；连接、同步项目、ETL 任务（含键列留空）、专属迁移与 TLS 证书配置均无需迁移。运行环境仍需 Java 17 或更高版本。
