# Jync v2.4.6 · 轮询与 CDC 稳定性

## 本版概要

v2.4.6 集中修复轮询续传、无主键增量与日志 CDC 的稳定性问题，并让同步进度卡实时刷新。建议所有 2.4.x 用户升级。

## 新增

- 设置页「项目与作者」加入 Docker Hub 入口与 Docker Sponsored OSS 认证标识。
- AI 运维助手新增运行环境查询（`runtime_info`）：当前版本、最新版本、更新状态与容器 / jar 部署方式。

## 优化

- 同步进度卡自动回填策略 / 游标列，大表全量完成后不再需要刷新页面。
- 没有未完成的全量时自动隐藏「全量进度」列，停在中途可续传时保留。
- 状态轮询改用投影查询，刷新时不再读取检查点与游标的 LOB 字段。
- 全量加载的行数估算由逐表目录查询改为一次 schema 统计并缓存 5 分钟。
- PG 逻辑 CDC 单周期消费上限可配（`sync.cdc.pg.max-rows-per-cycle`，默认 10 万行），繁忙积压不再每 1000 条重连。
- AI 助手知识库与提示词补充进度卡刷新规则、SQL Server 延迟口径与 Docker 升级引导。

## 修复

- 检查点按表名大小写不敏感匹配，修复大写表名续传状态丢失。
- 外键依赖排序始终优先于行数排序，修复缺行估算时可能先装子表。
- 无主键增量窗口改为整窗提交，修复中途失败重放写入重复行。
- CDC 基线瞬时故障不再被误置为 ERROR，保留锚点等待重试。
- YStream 先持久化位点再确认，避免强制终止后位点丢失。
- 重建基线 / 恢复位点前始终检查其他存活节点的租约，避免删除对方位点。
- 停止 CDC 消费者时不再持管理器锁等待线程退出，避免阻塞其他项目的启停。
- SQL Server CDC 延迟改为按 `cdc.lsn_time_mapping` 采样，修复面板恒为 0。
- 轮询替换状态内容后新出现的提示图标仍可悬浮显示（改为事件委托绑定）。
- 全量进度摘要的「已写入行数」改为当前表自身的进度，并忽略未选中表遗留的检查点，修复与表格行数字不一致。

## 测试

6804 个测试：6800 通过；3 个 TLS 证书用例受本机证书配置影响，1 个仅限 Linux 的用例在 macOS 上跳过。

## 升级

- jar：备份数据目录后替换 `jync.jar` 并重启，或使用「系统信息 → 一键升级」。
- 容器：拉取 `vfaner/jync:2.4.6`（或 `latest`）后重建容器，数据卷保持不动。
