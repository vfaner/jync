# Jync v2.4.6 · AI 运维助手与大表同步增强

## 本版概要

v2.4.6 让 AI 运维助手可以查询逐表状态并通过确认卡调整任务参数，重做大表全量、行数核对与 CDC 基线续跑，同时修复轮询与 CDC 的一批稳定性问题。建议所有 2.4.x 用户升级。

## 新增

- AI 助手可查询任务详情与逐表同步状态（含未开始表）并解释增量状态。
- AI 助手可通过确认卡调整任务参数、游标列、调度 Cron 与连接驱动参数，带权限、停止校验与审计。
- 管理员可通过 AI 调整 9 项系统性能参数，保存后热生效、多节点约 30 秒收敛。
- AI 助手新增运行环境查询：版本、更新状态、容器或 jar 部署方式。
- 精确行数核对改为后台任务，支持快速估算、超时/取消、单批最多 50 张表。
- 支持按外键波次的多表并发装载，父表完成后才装载子表。
- 未完成的 CDC 基线可从检查点继续，不必整项目重来。
- 全表同步状态合并为「各表同步进度」，包含未开始表并实时刷新。
- 游标列改为图标选择器，`SERVER_ID_CONFLICT` 错误提示中文化。
- 设置页「项目与作者」加入 Docker Hub 入口与 Docker Sponsored OSS 认证。

## 优化

- 全量分块按列宽与表统计自适应，块级失败换新连接重试；串行全量按行数让小表优先。
- 状态轮询改用投影查询，并共享一次检查点与行数统计，降低大表项目开销。
- 策略/游标列与各状态列随 2/5 秒轮询自动刷新，无需刷新页面。
- 没有未完成的全量时自动隐藏「全量进度」列，停在中途可续传时保留。
- MySQL 流式读取关闭默认服务端读超时，降低宽表全量连接中断。
- PG 逻辑 CDC 单周期消费上限可配（默认 10 万行），繁忙积压不再每 1000 条重连。
- AI 知识库与提示词补充进度卡刷新、标识符大小写、策略切换、全量语义与 Docker 升级说明。

## 修复

- 检查点按表名大小写不敏感匹配，修复大写表名续传状态丢失。
- 外键依赖排序始终优先，引用不完整或并发槽为空时回退串行，已取消的行数任务不再继续执行。
- 无主键增量窗口改为整窗提交，修复中途失败重放写入重复行。
- CDC 基线未完成时拒绝切换到轮询/全量比对，避免半截基线被当成完成。
- CDC 基线瞬时故障不再被误置为 ERROR，YStream 先持久化位点再确认。
- 重建基线 / 恢复位点前检查其他存活节点的租约，停止消费者不再阻塞其他项目启停。
- SQL Server CDC 延迟改为按 `cdc.lsn_time_mapping` 采样，修复面板恒为 0。
- 修复 INSERT-first 全量插入行数统计，以及全量进度摘要与表格行数不一致（摘要改为当前表自身进度）。
- 轮询替换状态内容后新出现的提示图标仍可悬浮显示（改为事件委托绑定）。

## 测试

6804 个测试：6800 通过；3 个 TLS 证书用例受本机证书配置影响，1 个仅限 Linux 的用例在 macOS 上跳过。

## 升级

- jar：备份数据目录后替换 `jync.jar` 并重启，或使用「系统信息 → 一键升级」。
- 容器：拉取 `vfaner/jync:2.4.6`（或 `latest`）后重建容器，数据卷保持不动。
