# Jync v2.4.7 · 一源多目标、外部基线、目标标识符大小写与达梦原生自增

## 本版概要

v2.4.7 是一次大版本更新：新增**一源多目标（fan-out）**、**外部基线接入**、
**自动同步新增表**与**CDC 自动补齐可空列**；新增目标标识符大小写开关与达梦 8
原生 `AUTO_INCREMENT`；并集中修复日志 CDC、fan-out 与轮询中会导致静默丢数据或
反复重跑全量的边界。建议所有 2.4.x 用户升级。

## 新增

- **一源多目标（fan-out）**：一份源数据同时分发到多个数据库目标，支持 MySQL binlog、
  PostgreSQL 逻辑解码、Oracle / 达梦 LogMiner、SQL Server CDC、崖山 YStream 六类日志源；
  每个目标独立位点、进度、worker 与中转（本地 spool 或 Redis Stream），基线只读源一次，
  目标并行写入。支持逐目标缺表自愈、DDL 待办分发、状态面板按目标展示、目标上限可配置
  （默认 20，`sync.fanout.max-targets` 可到 100）。
- **外部基线接入**：目标已由一致性 dump 灌好时，可录入源位点跳过全量直接从该点回放；
  支持 MySQL（File+Position+可选 GTID）、PostgreSQL（LSN+slot）、SQL Server（LSN+捕获实例）、
  Oracle/达梦（SCN）、崖山（RESTART_POSITION），接入前按引擎校验位点范围与归档/槽/捕获实例。
- **自动同步新增表**：轮询与全部日志 CDC 引擎在运行中自动发现新表并补基线；
  Oracle 自动补 `ALL COLUMN LOGGING`，SQL Server 自动建捕获实例，YStream 加入运行中服务。
- **CDC 自动补齐新增可空列**：单目标项目可自动执行仅含 `ADD COLUMN`、所有新列可空、
  无主键/唯一/自增/生成/引用约束的 ALTER；执行后保留「补齐缺失数据」待办。
- **目标标识符大小写**：Oracle 系目标可选「保持源端大小写」，按源端/映射拼写加双引号建表与写入；
  非 Oracle 系目标不显示该开关。
- **达梦 8 原生自增**：整数主键自增列使用 `AUTO_INCREMENT`，字典可见、显式源 ID 可写、
  计数器自动跟随最大值；非主键/非整数仍用序列+触发器。
- **AI 助手**：新增只读工具 `project_ddl_tasks` 查询待执行/待回放的 CDC DDL 待办；
  `cdc_status` 增加 fan-out 每目标位点、worker 存活与最近错误。

## 优化

- MySQL 8.0.20+ 压缩事务（zstd `TRANSACTION_PAYLOAD`）正式支持，内层事件按有符号 TIME2 解码。
- fan-out 基线屏障超时后继续启动，只给已确认目标写进度；离线目标靠 spool 保留事件追平。
- Redis 中转在本次要跑基线时从流尾新建消费组，避免长期未裁剪 stream 重放全部历史；
  `XACK` 失败从 PEL 重放，外来条目 ACK 不推进裁剪水位。
- spool/Redis 坏记录与 spool 超限不再无限重启：目标本轮停下、写 `.failed`，下次启动重建基线。
- 全量分块在死锁/锁等待时换新连接重试；目标列可比较判定缓存 60 秒。
- 并行全量续跑检测源表收缩（truncate/重灌）并丢弃旧检查点；并行 worker 连接也应用目标约束开关。
- 轮询安全余量多回退 1 秒，修复严格下界漏掉边界行；预检不再触发自动同步写入选表。
- SQL Server 目标约束自愈；Redis 流裁剪开关、fan-out 统计去重与边界说明。
- 任务表单改为双卡片，目标选择改为整框标签下拉；fan-out 独立卡片与可搜索状态表；
  外部基线弹窗补齐位点/GTID/LSN/SCN 的获取方式、示例与悬停提示。
- 无法映射值日志节流、MySQL 缺表负缓存、跨大小写绑定降为 O(列)、项目缓存清理、
  NaN/Infinity 游标键、目标列名映射去重。

## 修复

- 压缩 binlog 事务此前被整体忽略，下一条普通事务会把位点推过它。
- `binlog_row_image` 为 MINIMAL/NOBLOB 时，缺列行镜像此前被逐行跳过并推进位点；
  现在停车并提示改回 FULL。
- GTID 恢复模式下主库切换导致 binlog 编号变低时，位点与 GTID 不再冻结。
- 自动补可空列后保留回放待办并记录缺口，不再把未回放的窗口标成完成；缺口回放要求任务停止。
- SQL Server 捕获实例缺列时停车并提示重建捕获实例，不再静默跳过该表的全部变更。
- Oracle LogMiner 归档发现只取本地可用归档并点名不可读文件；基线完成前校验 anchor 覆盖，
  减少 ORA-01291 反复重建；`DELETED=YES` 的旧行不再参与选文件。
- MySQL 流式结果中断（`Can not read response from server` / `EOFException`）按可重试处理，
  分块全量换新连接重试；连接/元数据失败不再被误判成“表不支持”而静默推进。
- ETL：MongoDB 采样外字段显式失败、ORA-00942 歧义提示、目标 schema 校验、跳过目标生成列。
- 一源多目标复审修复：落盘类型、目标重放、基线屏障、新增目标基线、连接并发、配置包重映射、
  删除项目清理 Redis Stream、绑定读取失败告警节流等。
- 变更日志「变更最多的表」不再包含任务级记录；错误详情两行省略并在悬停气泡中完整显示、可复制。

## 已知边界

- 达梦原生自增列不允许被 `ALTER ... MODIFY`（DM 错误 -2664），类型变更需重建目标表；
  已有表不会被自动转换。
- fan-out 基线超时后继续启动是可用性取舍：长期离线目标仍占用 spool，达到 2GB 后按致命错误
  处理并需要重建基线。
- 数值/自增游标仍按已提交最大值推进，先取号后提交的更小 id 只能靠行数审计兜底。
- 无主键表仍是单条流式全量，源端断流后整表重来；建议给大表加主键或使用可切片方案。

## 升级

- jar：备份数据目录后替换 `jync.jar` 并重启，或使用「系统信息 → 一键升级」。
- 容器：拉取 `vfaner/jync:2.4.7`（或 `latest`）后重建容器，数据卷保持不动。
- 开启「保持源端标识符大小写」前，需删除已存在的大写目标对象并重新基线；开启后
  业务 SQL 要带同样的引号大小写。
