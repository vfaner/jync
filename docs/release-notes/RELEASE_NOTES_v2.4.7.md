# Jync v2.4.7 · 目标标识符大小写、达梦原生自增与实时同步加固

## 本版概要

v2.4.7 增加 Oracle 系目标的「保持源端标识符大小写」开关与达梦 8 原生
`AUTO_INCREMENT`，完善一源多目标（fan-out）的分发可用性，并集中修复日志 CDC
与轮询中会导致静默丢数据或反复重跑全量的边界。建议所有 2.4.x 用户升级。

## 新增

- 项目级「目标表名/字段名保持源端大小写」，仅 Oracle 系目标（Oracle / 达梦 / 崖山）
  显示；开启后按源端或表名映射的拼写加双引号建表、写入与校验，目录查询使用同一口径。
- 达梦 8 目标：整数类型且属于主键的自增列使用原生 `AUTO_INCREMENT`，数据字典可见、
  显式源 ID 可直接写入、计数器自动跟随最大值；非主键/非整数类型仍用序列+触发器。
- MySQL 8.0.20+ 的 `binlog_transaction_compression`（zstd）正式支持：解包
  `TRANSACTION_PAYLOAD` 内层事件，按 payload 末尾提交；仍使用有符号 TIME2 解码。
- 一源多目标（fan-out）能力完善：一份源数据分发到多个目标，各目标独立位点与中转；
  基线屏障超时不再拖垮全局，Redis 新建消费组可避免重放历史，坏记录/超限不再无限重启。
- AI 运维助手新增只读工具 `project_ddl_tasks`：查询待执行/待回放的 CDC DDL 待办，
  带目标 SQL、错误与缺口表。
- 外部基线弹窗补齐位点/GTID/LSN/SCN 的获取方式与示例，包括“不知道精确位点时选
  确定早于 dump 的文件、位点填 4”的说明。

## 优化

- 全量分块在死锁/锁等待（40001/40P01、MySQL 1213/1205、SQL Server 1205、
  Oracle 60/54）时也换新连接重试。
- 目标列可比较判定按目标连接/表形状缓存 60 秒，不再每表每轮查一次目标目录。
- 无法映射值的 ERROR 日志按表/操作/列限流；MySQL 缺表增加负缓存。
- 跨大小写目标的列绑定由 O(列²) 降为 O(列)。
- fan-out 基线屏障超时后继续启动，只给已确认目标写基线进度；离线目标的 spool
  保留快照与后续事件，恢复后追平。
- Redis 中转在“本次启动要跑基线”时从流尾新建消费组，避免长期未裁剪的 stream
  重放全部历史；正常恢复仍从流头重放积压。
- `disableTargetConstraints` 现在对并行全量 worker 的连接生效，归还池前恢复；
  恢复失败直接 abort 物理连接，避免 `FOREIGN_KEY_CHECKS=0` 泄漏。
- 并行全量续跑检测源表收缩（truncate/重灌），必要时丢弃旧检查点重新加载。
- 轮询安全余量额外回退 1 秒，修复严格下界漏掉 `watermark - lag` 边界行；
  预检不再触发自动同步写入选表。

## 修复

- 压缩 binlog 事务此前被整体忽略，下一条普通事务会把位点推过它。
- `binlog_row_image` 为 MINIMAL/NOBLOB 时，缺失列的行镜像此前被逐行跳过并推进位点；
  现在停车并提示改回 FULL。
- GTID 恢复模式下主库切换导致 binlog 编号变低时，位点与 GTID 不再冻结。
- CDC 自动补可空列后保留“重试补齐”待办并记录缺口，不再把未回放的窗口标成完成；
  缺口回放要求任务已停止，避免旧行快照覆盖新行。
- SQL Server 捕获实例缺列时停车并提示重建捕获实例，不再静默跳过该表的全部变更。
- fan-out Redis `XACK` 失败不再吞掉，worker 从 PEL 重放；外来条目 ACK 不推进裁剪水位。
- spool/Redis 坏记录与 spool 超限不再无限重启：目标本轮停下、状态可见，spool 写
  `.failed` 标记，下次启动要求重建基线。
- 外部基线新增真实达梦自增与实际压缩 binlog 的回归测试。

## 已知边界

- 达梦原生自增列不允许被 `ALTER ... MODIFY`（DM 错误 -2664），类型变更需重建目标表；
  已有表不会被自动转换。
- fan-out 基线超时后继续启动是可用性取舍：长时间离线的目标仍会持续占用 spool，
  达到 2GB 上限后按致命错误处理并需要重建基线。
- 数值/自增游标仍按已提交最大值推进，先取号后提交的更小 id 只能靠行数审计兜底。
- 无主键表仍是单条流式全量，源端断流后整表重来；建议给大表加主键或使用可切片方案。

## 升级

- jar：备份数据目录后替换 `jync.jar` 并重启，或使用「系统信息 → 一键升级」。
- 容器：拉取 `vfaner/jync:2.4.7`（或 `latest`）后重建容器，数据卷保持不动。
- 开启「保持源端标识符大小写」前，需删除已存在的大写目标对象并重新基线；开启后
  业务 SQL 要带同样的引号大小写。
