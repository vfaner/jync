# Jync v1.7.5

本版新增 **AI 配置接入本地模型**（Ollama 预设 + 深度思考档位），并在**安全、结构同步、日志 CDC、类型转换**四个方面修掉一批已定位问题。

## 本次更新

### 新功能

- **AI 配置接入本地模型**：协议新增 `Ollama（本地）`预设，选中即填入 `http://localhost:11434/v1` 并收起密钥栏（本地模型不需要密钥），超时放宽到 300 秒
- **深度思考档位**：每个供应商可选 `跟随模型默认 / 关闭 / 低 / 高`。关闭可显著降低延迟；本地推理模型不关思考时，思考 token 会计入输出预算，`max_tokens` 偏小会让正文为空。`跟随模型默认`不发送任何相关字段，升级不改变已有供应商的请求
- **首启自动生成加密密钥**：全新部署不再使用发行包里的公开默认密钥，密钥落到数据库同目录的 `<库名>.key`（POSIX 权限 0600）。已有数据库与显式配置保持原行为
- **下载包 SHA-256 校验**：一键升级在体积与 zip 完整性之外再核对哈希，不匹配即失败关闭、运行中的 jar 不动；Gitee 无校验和时用同一 tag 到 GitHub 核对
- **目标连接建表权限预检**：目标账号没有建表权限时在连接测试阶段就报出来，并给出可直接照抄的 `GRANT` 语句，不再等到结构同步建表才报 ORA-01031

### 修复

- **Oracle 建表列子句顺序**：`DEFAULT` 移到 `NOT NULL` 之前，修掉 ORA-00907 / ORA-03076；目标侧类型判定补上 Oracle 原生浮点与 BIT 宽度
- **目标表已存在时反复建表失败**：按厂商码 955 识别重复对象（中文环境文案不再漏判），缺列改为自动补上，只增列、不改类型也不删列
- **空闲轮询刷假更新**：四个方言的 upsert 只在值确实有差异时才更新，源库没动不再计入「更新」
- **空闲轮询日志刷屏**：只有真的发生变更才记 INFO，否则降 DEBUG
- **失败摘要刷屏**：多条同因错误归约成一句，弹窗不再逐条弹出
- **LogMiner 不可复现的变更**：日志里缺列时不再把目标列静默写成 NULL（外联 LOB、MINIMAL 补充日志等情形）
- **LogMiner 挖掘会话 NLS**：时间戳不再渲染成带中文 NLS 的文本字面量；MySQL 时间文本按目标列类型绑定
- **SQL Server 增量停止**：中途停止时放弃半成品事务窗口，避免折叠出错误的 DELETE 并永久跳过尾部
- **类型映射与建表 DDL**：`BIGINT UNSIGNED` 溢出、PG enum / 数组的内部类型名、`TIME WITH TIME ZONE`、伪数字默认值（`NaN` / `0x1p4`）、DB2 自增列、MySQL 无键 `AUTO_INCREMENT` 等多处转换异常
- **JDBC 元数据空列名**：跳过 `COLUMN_NAME` 为 null 的行，不再让整表元数据读取失败
- **超长字段校验**：名称等字段超限由服务层显式拒绝并返回 400，不再是 500
- **一键更新脚本**：路径含单引号时按 POSIX 规则转义

### 测试

- 单元测试 1208 → **1338**，全量通过
- 新增覆盖：推理档位按协议落参、Ollama 端点解析与未知协议回落、upsert 差异守卫（含真库 IT）、SHA-256 校验与跨镜像核对、建表权限预检（Oracle 23ai 真库）、类型映射与列子句顺序、CDC 事务窗口截断

### 已知边界

- **openGauss 目标**的 upsert 无挂条件的位置，源库没动时仍会多报更新
- 空闲轮仍会重读并重发游标边界那一秒的行（有意的迟到事务安全余量），由目标侧守卫吸收

## 覆盖发布补充（2026-10-16 晚，版本号不变）

本版发布后数小时内又收口三项，仍以 **v1.7.5** 覆盖发布——包内版本号与发行说明一并刷新，下载链接不变。

### 修复

- **英文界面泄露中文**：协议下拉的 `OpenAI 兼容` / `Ollama（本地）`、数据库类型里的「自定义」，以及一键升级的状态与错误文案，此前都是写死的中文，切到英文界面这些位置照旧显示中文。现已全部改走语言包；并补上抓住这一类问题的守卫——旧守卫只查「有没有未翻译的 `??key??`」，对硬编码中文完全失明，新守卫按 CJK 码点扫描英文页面，另加中英语言包键一致性校验
- **推理档位说明与端点行为不符**：`关闭` 档能否生效取决于端点，官方 OpenAI 的推理模型并非都接受（o 系列最低是 `low`，`none` 仅 gpt-5.1 起有效，不支持的值端点会返回 400 `unsupported_value`）。界面帮助文案与代码注释按此订正，原先写的「最低到 minimal」不准确

### 新功能

- **Ollama 原生接口**：协议新增 `Ollama（原生接口）`，走 `/api/chat`。此前只能走 Ollama 的 OpenAI 兼容端点，只放行 `/api/*` 的部署用不了；而且原生 NDJSON 流会被当成「网关缓冲了整段回复」，**结果是回复为空**。现已按原生形状收发：`options.num_predict` 取代 `max_tokens`、回复取 `message.content`、流式逐行解析、思考开关用顶层 `think` 布尔（不通用的档位串不发）

### 测试

- 单元测试 1338 → **1383**，全量通过

> **已经装过 v1.7.5 的请注意**：覆盖发布不改变版本号，设置页的「一键升级」发现不了这次更新，需要手动下载 jar 替换（下载链接与上一版相同）。

## 升级

替换 jar 重启即可，表结构随 `ddl-auto: update` 自动演进；**升级前备份 `./data`**。停机期间源库变更重启后自动补齐。

也可直接在设置页用「一键升级」完成（新版本号可被更新检查正常发现，默认从 Gitee 下载，本版起带 SHA-256 校验）。
