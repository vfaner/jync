# Jync v2.4.0

## 新增

- **角色与资源归属**：账号分为系统管理员（`ADMIN`）、运维（`OPS`）与访客（`VIEWER`）三种角色。管理员不受限制；运维能查看全部资源，但新建、编辑、删除、运行只允许作用于自己名下的连接、项目、ETL 任务/批次、迁移、Redis 目标与 AI 之外的业务资源；访客仍然只读。归属按创建者账号记录，编辑他人资源、引用他人资源或对他人项目发起 AI 草稿/校验都会得到拒绝（HTML 转 `/?denied`，API 返回 403 JSON）。
- **本地 `ops` 账号**：空库启动会创建 `admin`、`ops`、`view` 三个账号，角色分别为管理员、运维、访客，默认密码都是 `123456`，首次登录强制改密。从旧版本升级时自动补一个 `ops` 账号；如果升级库已存在 OPS 角色账号（例如从配置包导入），则只记录标记、不再新建。用 SQL 删除 `ops` 后重启不会复活（一次性标记 `seed.local-ops` 保存在元数据库，不随配置包迁移）。
- **外部认证运维名单**：外部认证页在「管理员用户名」下新增「运维用户名」，逗号分隔、精确匹配；同时命中的用户按管理员处理。已经接入 SSO 的部署需要手动填写该名单，外部登录才会出现 OPS 角色，未填写时外部用户仍是访客。
- **AI 总开关**：系统配置页新增「AI 辅助」卡片，可以关闭或重新开启 AI。关闭后 AI 菜单、转写页的草稿按钮与所有 AI 接口一起失效（草稿与校验接口返回 403 `error.ai.disabled`）。`sync.ai.enabled=false` 是部署级硬关：页面开关置灰且无法覆盖，管理页面的提交会被拒绝并提示原因。
- **进程指标放开**：三种角色（含访客）都能查看 `/dashboard/process-metrics` 的 CPU、内存与线程指标，不再限于管理员。

## 优化

- 模板中的写入口按角色与归属分别门控：页面级「新建」按是否具备写权限显示，行级「编辑/删除/启停」按 `canEdit(owner)` 显示，系统配置、外部认证、告警、审计、AI 配置与配置包页面仍只对管理员开放。
- 配置包导出/导入保留资源归属与外部认证的运维名单；旧版本导出的包缺少这些字段时按空处理，可照常导入。

## 已知边界

- 升级前创建的连接、项目与任务没有归属（视为系统所有）：运维只能查看，不能编辑，也不能在新任务里引用；需要继续交给运维维护的话只能由管理员重建，或由管理员继续管理。管理员不受影响。
- 外部认证的运维名单需要显式填写：升级不会自动把任何外部用户提升为运维。
- AI 页面开关在单节点上立即生效；多节点部署各自缓存 5 秒，最迟一个缓存周期后收敛。配置包导入后同理。
- 访客仍看不到需要写权限的页面配置（Redis 目标列表、迁移连接列表等），与 v2.3.0 一致；只读的业务资源列表不受影响。

## 升级

替换 `jync.jar` 并重启即可。元数据库启动时自动补齐新列：`oa_auth_config` 新增可空的 `ops_users` 列，资源表新增的 `owner_username` 保持为空（旧数据 = 系统所有）；`system_setting` 会写入一次性标记 `seed.local-ops`。删除不需要的 `ops` 账号不会影响其他账号。运行环境仍需 Java 17 或更高版本。
