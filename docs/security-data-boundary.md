# 数据边界与离线部署

本文面向私有化部署的运维与安全评审人员，说明 Jync 的数据落在哪里、什么情况下会主动访问外部网络、如何关掉全部出网能力，以及它在字段级加密、数据脱敏与国密算法上的实际能力边界。

## 1. 部署形态与本地落点

Jync 是自托管单体进程：业务数据只在「源库 → Jync 进程内存 → 目标库」之间流动，没有厂商 SaaS、没有遥测回传，也不依赖任何外部服务才能启动。

| 数据 | 默认位置 | 说明 |
|---|---|---|
| 元数据（项目、任务、连接配置、审计、告警地址） | `./data/jync.mv.db`，或 `SPRING_DATASOURCE_*` 指定的外部数据库 | H2 文件库或 MySQL 8 / PostgreSQL 16 / Oracle 23；连接密码与 Webhook 地址以 `enc:` 密文保存 |
| 加密密钥 | `./data/jync.key`（H2 形态下首次启动生成） | 所有 `enc:` 密文的解密密钥；POSIX 系统上以仅属主可读写（`0600`）创建 |
| 应用内 TLS 证书与私钥 | `./data/tls`（`JYN_TLS_DIRECTORY`） | 目录 `0700`、文件 `0600`；密钥库口令以 `enc:` 密文写在同目录边车里 |
| 运行日志 | `./logs/jync.log` | 不含密码、API Key 或完整 Webhook 地址；含库名、表名、错误摘要 |
| CDC 大字段溢写文件 | `${java.io.tmpdir}/jync-lob`（`sync.lob.spill-dir`） | 事务缓冲中超过 1 MB 的 LOB 原值，明文落盘，按事务边界删除 |
| 配置包（手工导出） | 管理员选择的下载位置 | 用导出时输入的口令加密；勾选「包含运行状态」时会带出更多配置 |

驱动 jar 由使用方自备（GBase、神通、GaussDB、HANA、ClickHouse、Hive、Impala、Elasticsearch、MongoDB 等），程序不会自动下载任何构件。

## 2. 出网点清单

库存安装默认只在更新检查时访问公网；其余出网点都需要管理员显式配置或启用。

| 去向 | 触发条件 | 默认 | 发出的内容 | 关闭方式 |
|---|---|---|---|---|
| `api.github.com` / `api.gitee.com` | 启动后与页面上的版本检查 | **开启** | 仅 HTTPS GET 读取 Release 元数据；带固定 `User-Agent: jync-update-check`，不含业务数据、主机名或账号 | `APP_UPDATE_CHECK_ENABLED=false`（`app.update-check.enabled`） |
| 管理员配置的告警 Webhook（钉钉 / 企业微信 / 飞书 / 通用 JSON） | 产生告警或恢复通知时 | 关闭（地址为空） | 告警文本：项目名、表名、失败/积压摘要与计数 | 清空告警地址，或停用告警；地址加密存储 |
| AI 辅助端点（OpenAI 兼容 / Anthropic / 原生 Ollama） | 仅在**已配置提供方且界面启用**后，用户点击过程转换/诊断时 | 关闭（无提供方） | 待转换的存储过程/函数 SQL 文本与提示词；API Key 随请求头发往所配置的端点 | `SYNC_AI_ENABLED=false` 整体下线；或删除提供方配置。纯内网可指向本机 Ollama（`http://127.0.0.1:11434`） |
| 源库、目标库、外部元数据库 | 同步、结构同步、ETL、CDC | 仅管理员配置的库 | 业务数据与 SQL | 不配置即不连接 |
| Elasticsearch / OpenSearch / Easysearch 端点 | 专属迁移预检、索引发现与写入 | 仅管理员配置的端点 | 索引名、settings/mappings、文档内容 | 不创建专属连接即无访问 |
| 企业统一认证网关（网关头模式 / 回调校验） | 已启用外部认证时 | 关闭 | 认证请求与身份头 | 使用本地登录；相关地址由环境变量配置 |

明确没有的能力：无埋点、无崩溃上报、无远程日志、无 CDN、无外部字体；页面与静态资源全部随包分发，`https://github.com`、`https://gitee.com` 等链接只在用户点击时打开浏览器，程序本身不会请求。会话、审计与版本检查都不上传业务数据。

> 元数据库若换成远程 MySQL/PostgreSQL/Oracle，元数据（含 `enc:` 密文）会离开本机到该数据库，这是管理员选择的部署拓扑，不是隐式外发。

## 3. 本地数据保护

### 3.1 连接密码与 Webhook 地址

- 算法：Spring Security `Encryptors.delux`（AES-256-CBC，每个值独立随机 IV），密文带 `enc:` 前缀。
- 密钥：`sync.crypto-password` / `sync.crypto-salt`，或首次启动生成并写入 `./data/jync.key`。
- **外部元数据库没有本地 H2 文件可依附**：此时必须显式设置 `SYNC_CRYPTO_PASSWORD` / `SYNC_CRYPTO_SALT`（建议放 Secret）。未设置时会退回发行包里的公开默认值，`enc:` 只相当于混淆——这是多实例部署最容易被忽略的一条。
- `data/jync.key` 等同于全部存量凭据的钥匙：不要放进配置包、不要提交到代码仓库，备份数据卷时按密钥材料保护。丢失后只能重新录入连接密码；泄露后应更换所有数据库口令并轮换密钥。

### 3.2 应用内 TLS

上传的证书与私钥只写入 `./data/tls`，密钥库口令以同一套 `enc:` 机制加密写进边车文件；页面、日志、审计与异常信息都不回显口令。证书不进入配置包，换机时需要重新上传或随数据卷恢复。

### 3.3 日志与审计

日志和审计记录管理员动作、库/表/任务标识、错误摘要与计数，不记录连接密码、AI API Key 或完整 Webhook 地址（审计里只出现脱敏后的主机与摘要）。如合规要求日志也不得出现表名或业务标识，应通过日志采集侧的脱敏规则处理。

### 3.4 CDC 大字段溢写

CDC 回放时，单个超过 `sync.lob.cdc-spill-threshold-bytes`（默认 1 MB）的值会先写到 `sync.lob.spill-dir`，事务提交/回滚后删除；启动时清理超过 `sync.lob.spill-retention-hours`（默认 24 小时）的残留，目录总量受 `sync.lob.spill-max-bytes`（默认 1 GiB）约束。这些文件是**未加密的业务原值**：

- 把 `sync.lob.spill-dir` 指向加密卷/受控目录，或
- 设 `sync.lob.streaming-enabled=false`，让大字段内联处理（不会落盘，但占用更多堆内存；1.7.7 之前的行为）。

### 3.5 配置包

手工导出的 `.jync` 包用口令加密，包含数据库连接、项目与（可选）运行状态；接入信息里可能有内网地址与账号名。按密件管理，不要走邮件/IM 明文传递。

## 4. 完全离线（air-gap）部署清单

```bash
# 关闭两个外部能力（容器部署可直接作为环境变量）
APP_UPDATE_CHECK_ENABLED=false
SYNC_AI_ENABLED=false
# 使用外部元数据库时必须显式设置；H2 部署可省略（首次启动自动生成 key 文件）
SYNC_CRYPTO_PASSWORD=<强随机值>
SYNC_CRYPTO_SALT=<强随机值>
```

```yaml
# 可选：避免 LOB 明文落在系统临时目录
sync:
  lob:
    spill-dir: /secure/jync-lob
```

1. 不配置告警 Webhook，或只指向内网告警网关。
2. 需要 AI 能力时使用本机 Ollama；不需要则保持 `SYNC_AI_ENABLED=false`，菜单与接口一并消失。
3. 应用内 HTTPS 使用自签证书或内部 CA 签发证书；续期离线完成。也可以继续由前置反向代理终止 TLS，Jync 只监听内网 HTTP。
4. 防火墙只放行「Jync → 源库 / 目标库 / 元数据库」与管理员访问端口，其余出站全部拒绝。版本检查会静默失败，同步与页面功能不受影响。
5. 需要离线升级时，把发行 jar 与 SHA-256 摘要带入内网；系统信息页的「检查更新」在无网时不可用，但可直接替换 jar 并重启。

### 验收方法

```bash
# 运行中的进程实际建立了哪些连接（Linux）
ss -tpn | grep java
# 或按 PID 只看外连
lsof -nP -p <pid> -iTCP -sTCP:ESTABLISHED
```

- 关闭版本检查并重启后，稳定运行期间应只看到到源库/目标库/元数据库的连接。
- 在出口防火墙做一次「除数据库网段外全部拒绝」的演练，确认页面、同步、结构同步、CDC 均正常。
- 页面源码与静态资源不引用外部 CDN/字体；`grep -RhoE "https?://[^\"'<> ]+" src/main/resources/{templates,static}` 的结果应只有文档链接与示例占位符。

## 5. 合规能力边界

| 能力 | 现状 | 说明 |
|---|---|---|
| 数据不出域 | **满足**（按本文关闭出网点后可完全离线） | 自托管、无遥测、无厂商回传 |
| 传输加密 | 支持应用内 TLS 1.2/1.3，或由前置代理终止 TLS | 使用 JDK/JSSE 套件；国密 TLS 未内置 |
| 静态数据加密 | **不提供字段级加密** | 依赖数据库 TDE、表空间加密、磁盘/卷加密；连接密码与 Webhook 地址是应用侧唯一加密存储的敏感配置 |
| 数据脱敏 | **提供写入目标的静态脱敏** | 列清洗支持手机号、身份证、银行卡、姓名、邮箱五类格式保留掩码，以及确定性 SHA-256 哈希；源库不变，页面预览仍对管理员显示原值 |
| 交易/业务字段加密 | 不支持 | 需要在源端、数据库函数或目标端自行实现 |
| 国密算法（SM2/SM3/SM4） | 未实现 | 应用侧使用 AES-256-CBC（配置密文）与 JSSE TLS 套件 |

### 需要等保/密评时的推荐做法

- **字段级加密**：优先用数据库自身的 TDE 或列级加密函数（如支持 SM4 的国产库），不要把加密放在同步工具里——它会破坏增量比较、下游关联与索引使用。
- **国密 TLS**：在 Jync 前面部署通过认证的国密网关（铜锁/Tongsuo Nginx、国密硬件或云网关），网关到 Jync 走受控内网明文；Jync 本身不承担国密终结。
- **脱敏**：用列清洗在目标端做静态脱敏；若需要同一数据对不同角色展示不同结果，应在目标库上建视图/行级权限，或在应用层实现动态脱敏——Jync 的页面预览不做动态脱敏。
- **密码模块合规**：AES-256-CBC 与 JSSE 不属于国密密码模块；密评要求「密码算法、密码模块均合规」时，需由外部密码机/网关承担，应用侧不宣称满足。
